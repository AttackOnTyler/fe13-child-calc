# Death after marriage: child recruitment and inheritance (FE13 / Fire Emblem Awakening)

Resolves #17 (part of #1). Researched 2026-09-23.

## Summary

**A parent who dies (is lost in Classic mode) after reaching S-support does not block the child.** Marriage is what triggers the child's paralogue. Nothing in any source lists "the parent must be alive" as a condition. Every child except Severa and Noire can be talked into joining by **Chrom**, not only by the fixed parent. Severa joins by talking to a villager, and Noire joins automatically.

The JP 2ch atwiki (SF's upstream) states it directly: when a parent has been lost in Classic mode, the child is built from **that parent's stats and skills as they were just before the loss**. In other words, the child still joins.

**What changes with a dead variable parent:**

- The *dynamic* inputs are frozen at the moment of death: the parent's current stats, which feed the child's starting-stat bonus, and the inherited skill (the parent's last/bottom-slot skill).
- The *static* inputs are unaffected, because they depend only on who the parent is: growths, cap modifiers, class sets and hair colour.

Normally all inheritance is locked in when you enter the paralogue. For a dead parent, "entering the paralogue" effectively reads the snapshot taken at death.

**Other cases:**

- **Robin.** Robin's death is always a Game Over, so it can't happen in a kept save. The same goes for Chrom, who is a main character.
- **No marriage.** If a parent dies *before* any S-support, there is no marriage, so the paralogue is never generated and the child doesn't exist.
- **Exception: Chrom's forced marriage.** If Chrom has no S-support by the end of Chapter 11, he automatically marries a candidate, and the JP wiki notes that a candidate lost in Classic *is still eligible*. So Lucina's mother (and Lucina's younger sibling's line) can be a dead unit.

**Rule for the tool:** a death after marriage **does not hard-block** the child or the child's own pairings. Model it as "the dead parent's stats and skills are frozen at time of death", not "the child is unavailable". The ⚠ default in #16 ("yes, the child still comes") is correct.

## UNVERIFIED

- **U1**: The specific case "married, then lost, *before* clearing Chapter 13". I found no source that describes it explicitly. E1 and E2 say the paralogue is keyed on marriage, and none lists survival as a condition, so it should still appear. Confidence is medium-high, but there is no hands-on report.
- **U2**: That a dead parent's growths, cap modifiers and class sets pass exactly as for a living parent. No source addresses death here specifically. It follows from these being derived from parent *identity*, not current state (see the `research/stat-inheritance` and `research/marriage-and-classes` branches). Confidence is high, but it is inference.
- **U3**: Exactly *when* the "before loss" snapshot is taken: the last save before death, or the unit's state at the moment it falls, including XP earned during that fight. E6 says only 「ロスト前」 ("before the loss"). For the tool, treat it as "state at death".
- **U4**: The lore claim that married parents "retreat" rather than die. It comes only from forum speculation (E11) and is irrelevant to mechanics.
- **U5**: Whether Owain can be recruited by Chrom. The JP-2ch paralogue 5 page has one old comment saying "Chrom unconfirmed", but Tanas Manor and JP-2ch p.27 both say Chrom or the mother, so this is effectively settled.

## Implications for the tool

1. **Do not hard-block.** A parent dead after marriage keeps the couple valid. The child stays available, and so do the child's own pairings: second-generation pairings, and Morgan/Lucina as mothers or fathers where that applies.
2. **Freeze, don't remove.** Store a flag such as `parent.lostAt` or `frozen: true`. When it is set, the parent's skill loadout and stats become read-only inputs for inheritance. The tool should warn if the planned inherited skill (the bottom slot) differs from the one equipped at death, or if the planned stat-bonus inputs assume growth after death.
3. **Static inheritance is unchanged.** Growths, cap modifiers and class sets need no special-casing.
4. **An unmarried dead unit ends its lines.** A dead unit that never reached S-support contributes no child. The only exception is Chrom's forced-marriage candidate after Chapter 11.
5. **Robin and Chrom** can never be "dead" in a live save; the tool can reject that state.
6. Keep U1 and U3 as editable ⚠ assumptions in the roster-state prototype (#16). The default for both is "child still comes; snapshot at death".
