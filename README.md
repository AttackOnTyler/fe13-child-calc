# FE13 Child Calc

**Use it here: https://attackontyler.github.io/fe13-child-calc/**

A planner for Fire Emblem Awakening (FE13) runs. It compares every possible parentage of every child unit side by side, finds the best set of marriages for your whole army, and then follows your run map by map.

It runs entirely in your browser. There is nothing to install and no account: your run is saved in your browser's local storage, on that device only.

## What it does

- **Compares children's pairings.** Pick a child to see every variable parent (and Robin's asset/flaw, and a second-gen parent's own parent) as one table row, with the child's caps, modifiers, growths, Spd against its target, class set and inheritable skills. **All children** is a leaderboard across every child.
- **Plans the whole roster's marriages.** The **Plan** view picks marriages for every child at once, weighed by each child's priority, your deployment roles and quotas, and what Robin is worth to each child. Pin the marriages you want, rule out the ones you don't, and lock Robin once you've decided.
- **Tracks a real run.** The **Roster** view holds your run facts (difficulty, Classic/Casual, route, Robin), each unit's state (available, benched, missed, dead) and the marriages that have actually happened. When a unit dies or a plan breaks, the plan shows what broke and what replaces it.
- **Follows you map by map.** The **Run** view has the chapter log and each map's chapter data: threats, danger flags, the chapter guide, and a preparation page with deployment, loadouts, supplies, seals and promotions.
- **Shows each unit on its own.** The **Units** view has every unit's page: class tree, skills, builds and what it passes on to its children.

## How to use it

1. Open the [site](https://attackontyler.github.io/fe13-child-calc/).
2. Open **? Guide** in the header. It walks you through one of three journeys and ticks each step off as you do it:
   - **Fresh run**: "who should everyone marry?" Set up the run on Roster, then plan.
   - **After a loss**: a unit died, or a marriage went off-plan. Record what happened and see what the plan becomes.
   - **Explore**: no steps, just questions that each jump to the view that answers them.
3. For a fresh run, roughly:
   1. **Roster › Run facts**: set difficulty, mode and route. The route also sets the **play context** (Apotheosis, Main story, Full route or All), which decides what builds are scored for.
   2. Set Robin's gender and asset/flaw now, or leave Robin open and let the plan weigh the options.
   3. Tick who you'll deploy and their role; bench who you won't field.
   4. **Plan**: read the marriage plan, set each child's priority, pin or rule out marriages, then lock Robin and create them in the game.
4. As you play, record real marriages and losses on **Roster**, and use **Run** for each map.

Your run and preferences stay in this browser. **Clear all** on Roster resets the run's facts, unit states and marriages; your scoring and plan preferences survive it.

## Where the data comes from

- **Game data** (units, classes, skills, inheritance, chapter maps) is cited from [Serenes Forest](https://serenesforest.net/awakening/) and the [Fire Emblem Wiki](https://fireemblemwiki.org/). Chapter data is generated by the scripts in [`scripts/chapter-data`](scripts/chapter-data/README.md) from fixed wiki revisions.
- **Curated data** (skill ranks, builds, synergies, unit opinion, the chapter guide) is opinion layered on top, and every entry cites a named source in [`src/curated/sources.ts`](src/curated/sources.ts). Game data never depends on it.
- The **Validation** toggle in the header shows the app's self-test, the assumptions it makes (which you can override), and how it resolved disagreements between sources.

## Running it locally

Requires Node 22.

```bash
npm ci
```

```bash
npm run dev
```

Other scripts: `npm test` (Vitest), `npm run typecheck`, `npm run build`. Pull requests are tested by [`.github/workflows/test.yml`](.github/workflows/test.yml), and pushes to `main` are tested and deployed to GitHub Pages by [`.github/workflows/pages.yml`](.github/workflows/pages.yml).

## For contributors

- [`CONTEXT.md`](CONTEXT.md) is the project's glossary: the terms the code and UI use (pairing, variable parent, class set, play context, and so on).
- `src/engine` is the pure logic (inheritance, scoring, the plan solver) and is where most tests live; `src/game-data` and `src/curated` hold the data; `src/ui` is the vanilla TypeScript front end.
- Issues are tracked on [GitHub Issues](https://github.com/AttackOnTyler/fe13-child-calc/issues).
